## A. 公式速查表

> 记号约定见 [01-地基](01-地基-坐标系统与价格.md)：
> $x$ = token0/A 的数量，$y$ = token1/ETH 的数量，$P = y/x$，$K = x \cdot y$，$L$ = V3/V4 流动性。

### A1. 恒定乘积

| 公式 | 什么时候用它 |
|---|---|
| $$x \cdot y = K$$ | 一切的起点。判断"这个操作有没有改变池子规模"——swap 不改变 $K$，加撤流动性改变 $K$。 |
| $$L = \sqrt{x_{virtual} \cdot y_{virtual}}$$ | V3/V4 里比较不同仓位的"深度"。注意用的是**虚拟**储备，不是真实储备。 |

### A2. 价格与冲击

| 公式 | 什么时候用它 |
|---|---|
| $$P = \frac{y}{x}$$ | **价格的定义式**。任何时候想知道价格，就用储备量相除；这也是"价格 = 状态点到原点的射线斜率"的代数表达。 |
| $$x = \sqrt{K/P} \qquad y = \sqrt{K \cdot P}$$ | 已知 $K$ 和 $P$，反推两个储备量。验算池子状态、推算套利后的储备分布时用。 |
| $$\Delta y = \frac{y \cdot \Delta x}{x + \Delta x}$$ | **算滑点**：投入 $\Delta x$ 个 A，实际要付出多少 ETH。 |
| $$\text{平均成交价} = \frac{y}{x + \Delta x}$$ | 检查"这笔交易的实际成交价有多差"。**它永远差于现货价 $y/x$**，差额就是滑点。 |
| $$-\frac{dy}{dx} = \frac{y}{x}$$ | 求**边际价格**（微分意义上的现货价）。推导曲线斜率、理解"价格是切线斜率"时用。 |
| $$\frac{\Delta P}{P} \approx 2\frac{\Delta x}{x}$$ | V2 里**快速估算价格冲击**。注意系数是 **2**（不是 1），且只在 $\Delta x \ll x$ 时近似成立。 |
| $$\frac{P}{P_0} = \left(\frac{y_0 + E}{y_0}\right)^2$$ | **往返定律**：已知累计净流入 $E$ 个 ETH，算价格变成了多少倍。复盘历史行情、反推资金流时用。 |
| $$\text{价格倍数} = \frac{1}{(1-a)^2}$$ | 移除比例 $a$ 的流动性后，价格会跳多少倍。评估"撤池子会导致什么"时用。 |
| $$\Delta\sqrt{P} = \frac{\Delta y}{L} \quad\Longrightarrow\quad \frac{\Delta P}{P} = \frac{2\Delta y}{L\sqrt{P}}$$ | **V3 专用**的价格冲击。因为 $L$ 是逐 tick 变化的，所以同一笔交易在不同价格上的冲击**完全不同**——这是"薄区价格跳变"的公式来源。 |

### A3. LP 持仓

| 公式 | 什么时候用它 |
|---|---|
| $$\text{ETH} = s\sqrt{K \cdot P} \qquad \text{A} = s\sqrt{K/P}$$ | **算你手里有多少币**。$s$ 是你的 LP 份额。注意两个式子都随 $P$ 变化，且方向相反。 |
| $$\frac{\text{ETH}}{\text{A}}\ \text{数量比} = P$$ | 快速判断当前构成偏向哪一边。也用于验证"数量比就是价格"。 |

### A4. K 的变化

| 公式 | 什么时候用它 |
|---|---|
| $$\frac{\Delta K}{K} \approx f \cdot \frac{\Delta x}{x}$$ | **估算手续费带来的 $K$ 增长**（小额交易近似）。注意 $K$ 的增长率小于费率本身。 |
| $$K' = K(1 \pm s)^2$$ | 加（$+$）或撤（$-$）比例 $s$ 的流动性后，$K$ 变成多少。**价值 $\propto \sqrt{K}$**，所以 $K$ 增 $2s$ 对应价值增约 $s$。 |

### A5. 无常损失

| 公式 | 什么时候用它 |
|---|---|
| $$IL(r) = \frac{2\sqrt{r}}{1+r} - 1, \qquad r = \frac{P_1}{P_0}$$ | **算全区间（V2）的无常损失**。$r$ 是价格倍数。结果恒为负；$r = 1$ 时 $IL = 0$，$r \to 0$ 或 $\to \infty$ 时 $IL \to -100\%$。 |
| — | ⚠️ 注意：**没有同样简洁的有限区间（V3）IL 公式**。V3 的 IL 要用 A3 的持仓公式算出实际持仓，再和"持币不动"对比，见 [08 章误区 7](08-误区纠正与安全检查.md)。 |

### A6. V3 集中流动性

| 公式 | 什么时候用它 |
|---|---|
| $$x_{real} = L\left(\frac{1}{\sqrt{P}} - \frac{1}{\sqrt{p_b}}\right) \qquad y_{real} = L\left(\sqrt{P} - \sqrt{p_a}\right)$$ | **算 V3 仓位的真实持仓**。这是最常用的 V3 公式。 |
| $$P=p_a:\ x_{real} = L\left(\frac{1}{\sqrt{p_a}} - \frac{1}{\sqrt{p_b}}\right),\ y_{real} = 0$$ | 区间**下界**的取值。用于确认"到达下界时 100% 是基础币"。 |
| $$P=p_b:\ y_{real} = L\left(\sqrt{p_b} - \sqrt{p_a}\right),\ x_{real} = 0$$ | 区间**上界**的取值。用于确认"到达上界时 100% 是计价币"。 |
| $$\left(x + \frac{L}{\sqrt{p_b}}\right)\left(y + L\sqrt{p_a}\right) = L^2$$ | V3 仓位的**曲线方程**。用于论证"集中流动性没有改变曲线形状，只是把双曲线平移了"。 |
| $$V = 2L\left(\sqrt{P} - \sqrt{p_a}\right) \quad \left(P = \sqrt{p_a \cdot p_b}\right)$$ | 价格在**区间几何均值**处时，算仓位的总价值。这也是唯一"两个币价值各占 50%"的位置。 |

### A7. tick

| 公式 | 什么时候用它 |
|---|---|
| $$P(i) = 1.0001^{i}$$ | 由 tick 序号算价格。每个 tick 对应 **0.01%** 的价格变化。 |
| $$i = \frac{\ln P}{\ln 1.0001}$$ | 由价格反推 tick 序号。计算"要覆盖某个价格区间需要设哪些 tick"时用。 |

### A8. 资本效率

| 公式 | 什么时候用它 |
|---|---|
| $$E = \frac{1}{1 - \sqrt{p_a/P}}$$ | **算集中流动性相对 V2 的深度倍数**（价格在几何均值处）。判断"这个区间值得做吗"的核心公式。 |
| — | 直觉：**区间越窄，$E$ 越大**。但窄区间也意味着更快出界，必须和 A9 的区间寿命一起看。 |

### A9. 区间寿命与宽度

| 公式 | 什么时候用它 |
|---|---|
| $$E[T] \approx \frac{\delta^2}{\sigma^2}$$ | **估算区间能活多久**。$\delta$ 是价格的对数半宽，$\sigma$ 是单位时间波动率。注意是**平方**关系——区间窄一半，寿命只剩四分之一。 |
| $$\delta^* \approx \sigma\sqrt{H}$$ | **决定区间该设多宽**。$\sigma$ 是波动率，$H$ 是你的计划持有期。这是区间宽度的起点建议，不是终点。 |

### A10. V4 费率

| 公式 | 什么时候用它 |
|---|---|
| $$\text{swapFee} = \text{protocolFee} + \text{lpFee} - \frac{\text{protocolFee} \cdot \text{lpFee}}{1{,}000{,}000}$$ | **算一笔 swap 的总费率**。协议费和 LP 费**不是简单相加**，是顺序施加的复合。 |
| $$50 + 3000 - \frac{50 \times 3000}{1{,}000{,}000} = 3049.85\ \text{pips} \approx 0.304985\%$$ | 代入实例。协议费 50 pips + LP 费 3000 pips。 |
| $$\text{V4 协议费上限} = 0.1\%\ (1000\ \text{pips})$$ | 协议费的硬顶。评估"协议最多能抽多少"时用。 |

### A11. V4 Hook delta

| 公式 / 规则 | 什么时候用它 |
|---|---|
| $$\text{swapDelta} = \text{swapDelta} - \text{hookDelta}$$ | **Hook 抽成的结算规则**。hook 的正 delta 由调用者承担。判断"这个 hook 能不能动钱"时用。 |
| $$\text{正 delta} = \text{hook 应收/已收} \qquad \text{负 delta} = \text{hook 应付/已付}$$ | Hook delta 的**符号约定**（源码注释原文）。读 hook 源码时用。 |
| `beforeSwap` 返回**恰好 96 字节** | 校验 hook 返回值格式。96 = 32（selector）+ 32（delta）+ 32（fee）。 |
| `afterSwap` 返回**恰好 64 字节** | 校验 hook 返回值格式。64 = 32（selector）+ 32（int128 delta）。 |
| 动态费率覆盖需 **23 位置位（`0x400000`）**，且值 $\le 1{,}000{,}000$ | 判断 hook 是否在覆盖费率、以及覆盖值是否合法。 |
| 挖地址期望尝试次数 $\approx 2^{14} = 16{,}384$ | 评估"部署一个有特定权限的 hook 要花多少算力"。 |
| `ALL_HOOK_MASK = (1 << 14) - 1` | 权限位的掩码。解码 hook 地址时先做 `address & 0x3FFF`。 |

## B. 关键数值速查

### B1. 主例子 A：A/ETH 基础池

```
池子：100 A + 10 ETH
K = 1000
P = 10/100 = 0.1 ETH/A
```

| 操作 | 结果 | $K$ | $P$ |
|---|---|---|---|
| 加 `+10 A / +1 ETH`（按比例） | `110 A + 11 ETH` | $1000 \to 1210$ | $0.1$（不变） |
| 加 `+20 A / +1 ETH`（不按比例） | `120 A + 11 ETH` | $1000 \to 1320$ | $0.1 \to \mathbf{0.0917}$ |

**用途**：验证"加流动性必然改变 $K$，要保持的是比例"（[08 章误区 2](08-误区纠正与安全检查.md)）。

### B2. 主例子 B：V3 窄区间仓位

```
当前价格 P₀ = 0.1
区间 [p_a, p_b] = [0.05, 0.20]
流动性 L = 10
```

| 价格 $P$ | A 数量 | ETH 数量 | 总价值(ETH) | A 占价值 |
|---|---|---|---|---|
| 0.03 | 22.36 | 0 | 0.671 | 100% |
| 0.05 | 22.36 | 0 | 1.118 | 100% |
| 0.07 | 15.44 | 0.410 | 1.490 | 72.5% |
| **0.10** | **9.262** | **0.926** | **1.852** | **50.0%** |
| 0.14 | 4.365 | 1.506 | 2.117 | 28.9% |
| 0.20 | 0 | 2.236 | 2.236 | 0% |
| 0.25 | 0 | 2.236 | 2.236 | 0% |

**关键性质**：
- 弧的两个端点**精确落在坐标轴上**：$(0,\ 2.236)$ 和 $(22.36,\ 0)$
- 区间方程：$\left(x + \dfrac{L}{\sqrt{p_b}}\right)\left(y + L\sqrt{p_a}\right) = L^2$
- $P < 0.05$ 或 $P > 0.20$ 时构成**完全冻结**，不再变化

**用途**：V3 持仓构成的完整渐变样本（[03 章](03-V3-集中流动性.md)）。

### B3. 主例子 C：MEME/ETH 往返

```
池子：100 ETH + 1,000,000 MEME
P₀ = 0.0001 ETH/MEME
K = 1e8
用户占 1% → 1 ETH + 10,000 MEME
```

| 场景 | 结果 |
|---|---|
| 涨 50 倍（$P = 0.005$） | 池子 = `141,421 MEME + 707.1 ETH`<br>用户 = `1,414 MEME + 7.071 ETH`<br>**IL = −72.3%** |
| 往返（涨 50 倍再跌回原点） | 仓位**回到起点**，两侧都多约 **0.258%**<br>$K$ **+0.516%**（价值 $\propto \sqrt{K}$）<br>**IL → 0** |

**费率陷阱**：

```
下行段收取的手续费：2,578 MEME
收取时的价值：      ≈ 1.8 ETH
崩盘后的价值：      ≈ 0.258 ETH
                      ↓
                    −85.7%
```

**用途**：论证"往返行情对 LP 友好，单向行情致命"，以及"手续费币种会贬值"（[08 章误区 8](08-误区纠正与安全检查.md)）。

### B5. 主例子 E：V3 区间出界的代价

```
MEME/ETH，入场 P = 1，区间 [0.9, 1.4]，投入 10,000
入场持仓：7,510.6 MEME + 2,489.4 ETH
```

| 价格 | 仓位 | 持币对比 | IL |
|---|---|---|---|
| $P = 1.4$（刚撞上界） | `0 MEME + 11,376.5 ETH` | $7{,}510.6 \times 1.4 + 2{,}489.4 = 13{,}004$ | **−12.5%** |

### B6. 资本效率表

公式：$E = 1/(1 - \sqrt{p_a/P})$。

**口径**：$E$ 一律在区间的**几何均值** $P^* = \sqrt{p_a p_b}$ 处取值（即仓位 50/50 的价格点）。

| 区间 | 宽度 | $E$ |
|---|---|---|
| $[0.05, 0.20]$ | ×2 / ÷2 | 3.4× |
| $[0.08, 0.125]$ | ±22% | 9.5× |
| $[0.09, 0.11]$ | ±10% | 20.4× |
| $[0.099, 0.101]$ | ±1% | **200.5×** |

**读法**：最后一行（±1%，约 200.5 倍）正是主例子 D 中 DAI/USDC 的 $E = 200.49$ 的来源。

**用途**：说明"区间越窄，同样的钱堆出的深度越大"（[03 章](03-V3-集中流动性.md)）。

## C. 术语表

> 排序方式：按**主题分组**，组内按英文首字母序。
> 标注 ★ 的术语是理解 V3/V4 的关键；标注 ⚠ 的术语是风险相关。

### C1. 核心机制

| 英文 | 中文 | 说明 |
|---|---|---|
| AMM (Automated Market Maker) | 自动做市商 | 用数学公式代替订单簿来定价的机制 |
| Bonding Curve | 联合曲线 | 单边定价曲线；价格由已发行量决定，**不需要 LP** |
| Constant Product | 恒定乘积 | $x \cdot y = K$，Uniswap 的核心约束 |
| Concentrated Liquidity ★ | 集中流动性 | V3 引入；把流动性堆在指定价格区间 $[p_a, p_b]$ |
| Exact-in / Exact-out | 指定输入 / 指定输出 | swap 的两种模式；决定了 delta 中哪个是 "specified" |
| Full Range | 全区间 | 覆盖价格 $(0, \infty)$；V2 的行为 |
| Geometric Mean | 几何均值 | $\sqrt{p_a \cdot p_b}$；只有在此价格上仓位才是 50/50 |
| $K$ | 恒定乘积 | $x \cdot y$。swap 不改变它，加撤流动性改变它 |
| $L$ | 流动性 | V3/V4 的深度度量，$L = \sqrt{x_{virtual} \cdot y_{virtual}}$ |
| $P$ | 价格 | $P = y/x$，即储备比，也是状态点到原点的射线斜率 |
| Price Impact | 价格冲击 | 交易本身造成的价格变动 |
| Range Order | 区间订单 | V3 的副产品；把仓位上限设得很窄就近似限价单 |
| Slippage | 滑点 | 实际成交价与预期价的偏差（含价格冲击与手续费） |
| sqrtPriceX96 | — | 合约中实际存储的量；$\sqrt{P}$ 的 Q64.96 定点表示 |
| Swap | 兑换 | 沿曲线滑动；$K$ 不变，价格变 |
| tick ★ | — | 价格的离散刻度，$P(i) = 1.0001^i$，每 tick = 0.01% |
| tickLower / tickUpper | 区间下界 / 上界 | 一个 V3 仓位的边界 |
| tickSpacing ★ | tick 间距 | 池子允许的最小 tick 粒度，由费率档决定 |
| Virtual Reserves ★ | 虚拟储备 | V3 计算用的"假想储备"；真实储备 = 虚拟储备 − 区间外部分 |

### C2. LP 与收益

| 英文 | 中文 | 说明 |
|---|---|---|
| APR | 年化收益率 | 收益的年化表达；LP 场景下必须扣掉 IL 才有意义 |
| feeGrowthGlobal ★ | 全局费用增长 | 每单位流动性累计收到的费用，X128 定点 |
| feeGrowthOutside ★ | 区间外费用增长 | 用 `global − below(tickLower) − above(tickUpper)` 在读取时算出区间内费用 |
| IL (Impermanent Loss) ★ | 无常损失 | 相对于持币不动的差额；价格回到原点则消失 |
| JIT Liquidity | 即时流动性 | 在大额交易前后极短时间内提供集中流动性以吃掉手续费 |
| Liquidity Mining | 流动性挖矿 | 用代币激励吸引 LP |
| LP (Liquidity Provider) | 流动性提供者 | 向池子注入双边资产的人 |
| LP Fee | LP 费率 | 归流动性提供者的那部分手续费 |
| LP Token | LP 代币 | 代表池子份额的凭证；V2 是 ERC-20，V3 是 ERC-721 |
| pips | — | 百万分之一；V4 费率的最小单位（$1\% = 10000$ pips） |
| Protocol Fee | 协议费 | 归协议金库的那部分；V4 上限 0.1%（1000 pips） |
| Rebalance | 再平衡 | 把区间重新居中到当前价格；会**兑现浮亏** |
| Yield | 收益 | 泛指 LP 获得的回报 |

### C3. V3 / V4 结构

| 英文 | 中文 | 说明 |
|---|---|---|
| BalanceDelta | 余额变动 | V4 中表示 token0/token1 两个方向的欠款或应收 |
| BeforeSwapDelta ★ | 交易前变动 | `beforeSwap` 的返回值；分 `specified` / `unspecified` 两部分 |
| Currency | 币种 | V4 中可以是 ERC-20，也可以是地址 0（原生 ETH） |
| Delta ★ | 变动量 / 欠款 | V4 闪电记账的核心；正数表示应收，负数表示应付 |
| Donate | 捐赠 | 直接把资产注入池子、不换取 LP 代币的操作 |
| Dynamic Fee | 动态费率 | 费率可由 hook 逐笔或定期修改 |
| ERC-6909 | — | V4 用其表示"索取权"，用于多跳结算与节省 gas |
| ERC-721 | — | V3 的仓位是 NFT（NonfungiblePositionManager） |
| Flash Accounting ★ | 闪电记账 | 整个交易过程中只记 delta，最后统一结算 |
| Hook ★ | 钩子 | 挂在池子上的外部合约，在关键动作前后被回调 |
| hookData ★ | 钩子数据 | 调用者透传给 hook 的任意 bytes |
| liquidityGross | 总流动性 | 某个 tick 上所有仓位的流动性之和 |
| liquidityNet ★ | 净流动性 | 跨越该 tick 时流动性的净变化量；实现 O(1) 跨界 |
| PoolId | 池子标识 | `PoolKey` 的哈希 |
| PoolKey ★ | 池子键 | `{currency0, currency1, fee, tickSpacing, hooks}`；唯一标识一个池子 |
| PoolManager ★ | 池管理器 | V4 的 Singleton 合约，管理所有池子 |
| salt | 盐值 | 用于隔离同区间仓位，或配合 CREATE2 挖出特定权限的 hook 地址 |
| Singleton ★ | 单例 | V4 把所有池子收进一个合约，建池只改一条 mapping |
| Subscriber | 订阅者 | V4 中可不转移 ERC-721 就参与质押的机制 |
| Transient Storage ★ | 瞬态存储 | EIP-1153；V4 用它存 delta，交易结束自动清零 |
| TWAMM | 时间加权平均做市 | 把大单拆成随时间线性执行的小单；V4 可用 hook 实现 |
| unlock / unlockCallback | 解锁 / 解锁回调 | V4 的入口模式：先 `unlock`，在回调里做操作，最后校验 delta 归零 |

### C4. 链上环境与风险

| 英文 | 中文 | 说明 |
|---|---|---|
| CEI (Checks-Effects-Interactions) | 检查-生效-交互 | 智能合约安全范式；写 hook 必须遵守 |
| Flash Loan | 闪电贷 | 无抵押瞬时借贷；常被用来放大对可操纵价格的攻击 |
| MEV | 最大可提取价值 | 通过排序、插队、夹击从交易中榨取的价值 |
| Rug Pull ⚠ | 抽地毯 | 项目方撤走流动性或砸盘跑路 |
| Sandwich Attack ⚠ | 三明治攻击 | 在受害者交易前后各插一笔，赚取价差 |
| Vampire Attack | 吸血鬼攻击 | 用激励把另一个协议的流动性和用户吸走 |
| WETH | 包装 ETH | V3 及更早版本中代表 ETH 的 ERC-20；V4 可直接用原生 ETH |
